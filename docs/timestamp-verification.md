# 时间戳工具验收记录

日期：2026-10-15。环境：macOS、Node.js 26.4.0、Chrome。

## 实现与开源复用

- 新增独立时间戳页面，沿用现有工具箱导航、样式、通知、Clipboard API 和多页面打包。
- 固定使用 MIT 开源依赖 `temporal-polyfill@1.0.6` 的局部 `implementation` 入口，兼容现有 Chrome 120 基线；没有增加前端框架、联网服务、扩展权限或输入存储。
- 秒与毫秒十进制整数双向转换；设备 IANA 时区默认值、手动选择、当前时间、单项和全部复制；夏令时歧义采用拒绝策略。
- 历史时区可能存在秒级偏移。独立审查发现 `ZonedDateTime.toString()` 默认将偏移舍入到分钟；已改为当地 ISO 时间加精确 `zoned.offset`，并接受输入的秒级偏移。这是保证历史日期往返准确所需的补充。

生产页面：`http://127.0.0.1:4177/timestamp.html`。已实际读取响应头，确认与扩展一致的 CSP：`script-src 'self'; object-src 'self'; style-src 'self' 'unsafe-inline'; worker-src 'self'; connect-src 'none'`。

| 场景 | 结果 |
| --- | --- |
| 默认打开 | 显示设备时区 Asia/Shanghai，当前时间每秒刷新 |

| 输入 `2024-01-01 08:00:00.123` | 得到毫秒 `1704067200123`，整数秒 `1704067200` |
| 切换加德满都 | 当地时间 `2024-01-01 05:45:00.123`，上下文显示 UTC+05:45，绝对时间点不变 |
| 纽约夏令时跳过和重复时间 | 两者均明确报错，旧结果清空，复制禁用 |
| 纽约重复时间加 `-05:00` | UTC 为 `2024-11-03T06:30:00.000Z`；切换 UTC 后毫秒数不变 |
| UTC 下 `-1` 毫秒 | 时间为 `1969-12-31 23:59:59.999`，整数秒为 `-1` |

| 单项复制 | 实际读取剪贴板，精确为 `1704067200123` |
| 复制全部 | 实际剪贴板含时区、单位、当地时间、UTC 和 ISO；毫秒完整保留 |
| 当前毫秒复制 | 剪贴板与点击时屏幕显示的毫秒值一致 |
| 剪贴板 API 不可用 | 临时夹具中显示失败提示，并选中完整结果，选择范围为 0 至 13 |

## 验收边界

浏览器控制工具无法绑定现有 `chrome-extension://` 页面；系统界面控制未获得权限，因此未在真实扩展协议下完成自动验收。以上浏览器操作基于生产构建和与扩展一致的 CSP，不等同于真实扩展加载验证。

使用时在 Chrome 扩展管理页重新加载本项目 `dist/`，再打开工具箱，确认左侧「时间戳转换」入口和复制操作。新工具未要求新增扩展权限。
