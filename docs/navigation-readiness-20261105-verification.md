# 编码、Cron 与时间戳切换闪屏：启动就绪时序修复

## 本轮复现与根因

直接加载已发布 v1.2.6 的 Chrome 扩展目录，用 Chrome for Testing 149.0.7827.55 连续切换“编码 → Cron → 编码 → 时间戳”20 次。CDP 实际画面记录共 377 帧，其中 6 帧出现只有“正在加载页面”的空框，顶栏、侧栏一起消失。对应点击为 6、8、10、14、16、18，两条用户反馈路径均复现。

`public/theme-init.js` 在原生页面过渡开始后设置独立的 350ms 超时。目标界面尚处于 `booting` 时，该超时已经撤掉旧画面，暴露了隐藏正文的启动占位。此前只采样 `ready` 之后透明度的回归，漏掉了点击至就绪之间的空框。

## 最小修改

- 只修改 `public/theme-init.js`：取消独立的 350ms 提前释放。目标就绪后立即释放旧画面，不增加固定等待。
- 复用原有 3 秒慢加载恢复入口：超过该时间仍未就绪才显示可重新加载的界面，避免一直停留在旧画面。失败与离页的释放路径继续保留。
- 新增 `test/e2e/extension-navigation-paint.spec.js`：在真实扩展中延迟就绪信号，验证 Cron、时间戳的等待画面和慢加载恢复，不再仅检查最终页面。

没有修改计算、导航地址、侧栏偏好、用户内容、权限和依赖。
