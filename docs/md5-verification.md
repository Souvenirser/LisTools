# MD5 摘要与校验验收记录

日期：2026-10-16。版本：1.2.0。入口：`convert.html#md5`。

MD5 复用 @noble/hashes 2.4.0 的 MD5、增量接口与 HMAC；表示转换复用 @scure/base，字符集复用现有模块，CSV 复用 PapaParse。未自行实现摘要算法。原有摘要默认 SHA-256 保留。

## 自动验证

- `npm test`：**209 项通过，0 失败**；MD5 核心覆盖 13 组测试。
- `npm run build`：成功。Chrome 120 构建目标保持；存在原有大型编辑器分包体积提示，不影响构建。
- [RFC 1321](https://www.rfc-editor.org/rfc/rfc1321) 全部标准向量、百万个 a；[RFC 2202](https://www.rfc-editor.org/rfc/rfc2202) 全部 7 个 HMAC-MD5 向量，以及空密钥、长密钥与 Node crypto 交叉验证。
- 大小写 Hex、中间 16 字符兼容值、原始摘要 Base64、严格比较、可省略的合法 Base64 补位；内部非法字符及长度错误均拒绝。
- 中文、emoji、GBK、UTF-16、BOM、NUL、前后空格、CRLF / CR / LF、Unicode 不同规范形式与孤立代理项。
- 逐行空行、末尾换行、重复行、跳过空行及上限；CSV 公式转义、JSON 文件名保真、导出顺序及不包含原文/密钥。
- 大于 50 MiB 的输入按 2 MiB 顺序读取，分块边界、空文件、读失败后继续、重复文件名、4 GiB 超限拒绝。
- Worker 进度/条目完成/最终完成协议，取消终止、过期事件隔离；多文件拖入只在明确启用的模式接受。
- 50 个 MD5 语言包各有 60 个翻译字段；键与插值参数一致。原有翻译保留。

## 真实 4 GiB 文件

在本机文件系统创建逻辑大小 **4294967296 字节**的零内容稀疏文件（不是用假 size 替代的对象），通过浏览器文件选择器交给生产页面。Worker 实际按 2 MiB 分块读取全部 4 GiB 内容。

Node crypto 独立流式计算与浏览器两次完整计算均得到：

```text
c9a5a6878d97b48cc965c1e41859f034
```

第一次完整计算期间切换阿拉伯语、Base64 和预期摘要，最终比对一致；第二次在最终构建中复验一致。该验收证明此环境能完成该文件，不代表所有设备的耗时或内存上限。

证据：浏览器结果 JSON（本地记录：`docs/md5-4gib-result.json`）、[文件结果截图](./md5-files.jpg)。
