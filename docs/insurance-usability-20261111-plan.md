# 五险一金计算器易用性修复方案（待实施）

2026-11-11。基于当前工作树、真实浏览器走查、Letvr 与瑞人云页面对照。本轮仅排查与设计，未修改产品源码。重新运行 412 项单元测试通过，新增浏览器探针复现的问题不在这些测试覆盖内。

## 1. 目标与方案取舍

普通用户进入页面，首先完成“我每月扣多少五险一金”，再了解公积金入账与单位承担。保留单位计算、实际基数、自定义、附带个税及全部导出能力。

考虑过三种方式：只改术语不能解决流程负担；全新分步向导增加点击和维护；推荐保留当前双栏，简化首屏，并让专业设置按需展开。此为推荐设计，尚未实施。

参考：Letvr（https://letvr.com/zh/cn-salary/）将月薪、城市、公积金与专项扣除放在主输入，费率折叠、结果分层；瑞人云（https://ssc.ruirenyun.com/calculator.html）分开社保/公积金基数，逐项目展示双方费用。只借鉴界面组织，不采用竞品税额和费率为正确性依据。

## 2. 已验证问题

1. 单位比例跟随个人已勾选时，仍能把单位比例从7改为12，保持个人7，结果按7/12计算。
2. 未启用附带个税，自定义可扣除额1000仍能阻断有效的缴费计算。
3. 公共基数输入bad，错误与焦点却落到空的分项养老基数。
4. 城市搜索Enter确认北京会同时提交计算，把空工资标红。
5. 上海可以显示“已核验”，但单位费用和用工成本又为“未确认”，状态缺少个人/单位范围。
6. 目录20城与实际可自动计算范围不同。当前政策清单仍记录京沪个人端可试算，其他18城需要核验/自定义；本轮未全面重验政策。

复现证据：`.superpowers/sdd/insurance-followup-20261111/probe.json`、`reproductions.log`、`keyboard-probe.json`。源码定位：`src/insurance.js` 的默认模板、read、run、比例事件与键盘提交；`src/tools/payroll/contributions.js` 的附税字段校验。

## 3. 默认流程与首屏

沿用insurance.html和insurance工具ID，默认只突出四项：

| 输入 | 默认/解释 |
| --- | --- |
| 参保城市 | 空白，由用户明确选择；搜索保持中文、拼音与英文别名 |
| 缴费月份 | 当前年月，政策严格按该月份匹配 |
| 税前月工资 | 空白，元/月 |
| 公积金个人比例 | 按当前可用政策给明确标注的试算值，可输入合规小数；没有有效默认时不预填 |

普通状态说明“按当前工资估算缴费基数，实际以申报为准”。城市匹配后直接显示当前可用范围和试算假设，避免多条重复说明。保留显式“本次不计算公积金”，映射现有参保开关，不把比例0误当合法政策内费率。

主按钮“计算每月缴费”紧随必要输入。其后是“我知道实际缴费基数”“更多缴费设置”“同时估算到手工资”“手动填写当地参数”。不要求普通用户先理解公共基数、税前可扣除额或应税调整。

比例联动：默认只编辑个人比例，并显示单位跟随的只读摘要。选择“分别设置个人和单位比例”后才能编辑单位比例。重新联动以个人比例为准，读取时也检查联动一致性。

## 4. 三种输入情况

### 按工资估算

默认路径。沿用现有各险种基数上下限与取整规则。结果说明哪些项目按下限/上限处理；不把当前工资试算描述成真实申报基数。

### 我知道实际基数

主区显示“社保缴费基数”“公积金缴费基数”；社保字段映射现有公共基数，公积金映射其单项覆盖。各险种不同的情况继续在分项设置覆盖。

分项实际基数优先于公共值，显示已单独设置的项目。修改公共基数不覆盖已有分项草稿。公共输入格式错误定位公共字段，某一项覆盖错误定位该项；范围错误显示实际采用值及允许范围，不静默改写实际基数。城市、月份变化保留草稿并重新校验。

### 手动填写当地参数

用明确次级入口替代孤立“自定义”复选框。保留城市和自定义各自的页面内草稿。自定义名称、基数、比例、固定额及参保开关分组展示，醒目标明“用户自定义，未经官方核验”。不得把未填写费率默认成0，也不得默认把其他城市参数套入。个人参数不全不能算个人；单位参数不全可保留个人结果，并指出缺少的单位项目。

只有启用附带个税后，才读取、校验税前可扣除额与应税调整。不启用个税时，无关税额草稿不阻断缴费。附税失败保留本次有效缴费，允许导出缴费，税额显示未生成且不含旧值。直接复用现有部分成功机制，不新建状态框架。

## 5. 结果组织

主要展示“个人每月扣款”，下分个人社保与个人公积金。随后显示“扣除五险一金后剩余（未扣个税）”。启用附税且成功时，以“预计本月到手”明确补充，附带同薪/同扣除估算条件。

第二组“公积金账户每月合计入账”展示个人+单位，明确不是到手现金。第三组“单位承担”展示单位缴费与用工成本；未知项注明原因，不写成0或假装精确总额。

明细统一为项目、采用基数、个人比例/金额、单位比例/金额、适用状态。生育合并、未参与、行业基准试算均显示具体文字。默认保留一份“复制摘要”和下载明细入口，专业单项复制放在明细中，避免每行都先出现复制按钮。

金额展示千分位和两位小数，机器数据与复制保持完整精度；条件快照包含城市、月份、基数方式、比例、排除项目、政策版本与自定义标记。显示与导出读取同一份结果。

## 6. 附带个税与城市可用性

附税复用刚改造的工资到手输入适配与扣除助手，月份始终跟随缴费月份；只需要月度专项扣除，任职/特殊口径按需展开。默认延续现有“同薪、同个人扣除”的估算口径，明确不是实际全年工资单还原。不得把本月缴费直接包装成历史每月真实缴费；需要精确累计时进入独立个税核对流程，条件承接须由用户显式触发，工资不进入网址或存储。

城市可用性展示为：个人与单位可试算、个人可试算/单位待补充、该月份缺少已核验政策。分别记录字段证据完整性与金额是否已知，不再只用一个“已核验”概括全部能力。城市选择面板提前标明当前月份状态，不等填完才阻断。

20城政策补齐仍是独立未关闭事项；本次UI修复不自动升级核验标记、不增加联网取政策。后续逐城从官方确认后再启用，不从竞品复制比例、不以旧参数外推新月份。

## 7. 布局与稳定性

沿用浅深主题、常驻工作台和现有1120px内容宽度。桌面输入/结果相邻，小屏上下排列；主要金额28–32px，正文16px，说明至少14px，触屏控件44px。高级分项使用有界区域，展开不把主操作推出很远。

城市搜索Enter只确认选项，普通金额输入Enter才提交；复制不触发失焦重算或重建按钮；同条件重算保留结果节点和阅读位置。语言、主题与缩放变化不重算、不丢草稿。固定栏沿用执行/查看结果机制，查看结果不重复计算；不强制滚动到结果。
